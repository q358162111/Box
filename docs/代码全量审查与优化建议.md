# Box（TVBox fork）全量代码审查与优化建议报告

> 审查对象：`atomgit.com/cai_hj/Box` @ `main`（commit `b3d5b2b`）
> 项目规模：约 5.9 万行 Java / 15 Kotlin / 10 JS / 6 Python，4 模块（app / quickjs / pyramid / xwalk）
> 审查方式：四路并行深度审查——① 爬虫框架与网络层 ② 播放器与核心页面 ③ 服务端/数据层/其余 UI ④ 安全专项审计；关键发现已逐条抽查源码验证属实
> 配套文件：安全专项完整报告见 `docs/安全审计报告.md`

---

## 一、总体结论

项目已历经 7+ 轮审查修复（git log 佐证），关键高危面（路径穿越、Zip Slip、SSRF 环回过滤、XStream 白名单、EventBus/Han­dler 泄漏清理）质量显著高于 TVBox 原版。但本次全量审查发现：

**当前最大风险已不是「没修过」，而是三类系统性病灶：**

1. **双胞胎类导致修复漏打**——`PlayActivity`（2408 行）与 `PlayFragment`（2324 行）为 95% 复制粘贴，历史上至少 3 处关键修复只落在 Fragment 一侧，Activity 仍是带病版本（本次 6 个崩溃级问题中 3 个直接源于此）；
2. **纸面修复**——`CacheManager` 的反序列化 ObjectInputFilter「注释宣称有、代码没有」；`LivePlayActivity` 的 Hashtable→LinkedHashMap「只写注释、代码未改」；`SubtitleLoader` 的流重建修复不完整；
3. **横向不一致**——同类问题只修「被点名的文件」（UserFragment 修了主线程 DB，History/Collect/Drive/Search 没修；UserFragment 清理了静态 Adapter，History/Collect 没清）。

**问题总量：崩溃/泄漏级 16 项 · 性能/健壮性级 33 项 · 风格/可维护性级 35 项 · 安全高危 3 项 + 中危 5 项。**

## 三、P1：本迭代应排期（性能 / 健壮性 / 中危安全）

### 性能与卡顿（TV 低端设备体感明显）

- **换台 Runnable 无限叠加**（`LivePlayActivity.java:919,958`）：每次换台 `post` 一个每秒自循环的 Runnable，从不 removeCallbacks，换 N 次台 = 每秒 N 次无效 UI 刷新，永不自愈。
- **主线程 DB/IO 至少 6 处**（`AppDataManager.java:104` 开启 `allowMainThreadQueries`）：HistoryActivity:151、CollectActivity:153、DriveActivity:198/417、SearchActivity:536-538（全表查询+全表 delete/insert）、BackupDialog 构造函数主线程 `listFiles`+递归删除。UserFragment 已修同款但未推广。
- **主线程同步解析配置缓存**（`ApiConfig.java:157-173`）：useCache 路径磁盘读+Hawk 落盘+全量 JSON 解析全在主线程，大配置 ANR 风险；与非 useCache 路径行为不一致。
- **字幕写盘在主线程**（`DefaultSubtitleEngine.java:99-105`）：数 MB 字幕 `getBytes()`+写文件+Hawk 持久化，可触发 ANR。
- **嗅探路径 30 秒超时**（`PlayFragment.java:1901-1911`、`JsSpider.java:74`）：每条资源 URL 一次 `callWithTimeout(30s)`，JS 侧挂起时页面冻结；首次加载还在 WebView 回调线程同步做网络 IO。建议嗅探单独 1-2s 短超时+结果缓存。
- **每秒 new SimpleDateFormat ×5 处**（VodController:1151、BaseController:135、LivePlayActivity:769、HomeActivity:122）：长期播放持续 GC 压力，可缓存为字段。
- **`getSearch/getQuickSearch` 无超时保护**（`SourceViewModel.java:626,714`）：其余方法已走 `callSpiderWithTimeout(15~20s)`，唯搜索路径裸调用，5 个卡死源占满搜索线程池后全局搜索无响应。
- **HtmlParser ThreadLocal 大对象驻留**（`HtmlParser.java:22-29`）：cachedThreadPool 数十线程各驻留 2 份 Jsoup Document（可达数 MB），建议 WeakReference 包装。
- **Python.start() 在主线程**（`pyLoader.java:20-23`）：Chaquopy 初始化数百毫秒~数秒计在首帧内。

### 健壮性

- **getSpider check-then-put 竞态 + recentJarKey 全局路由竞态**（`JarLoader.java:154-239`、`JsLoader.java:139-180`）：多源并发时代理请求按「最后加载的源」路由，图片/播放地址/弹幕串源——典型偶发数据错误。修复：`computeIfAbsent` 原子化 + proxyInvoke 按 params 中 siteKey 路由。
- **SourceViewModel.getPlay 线程池竞态**（`SourceViewModel.java:793-843`）：lambda 读可变字段，旧任务可提交到新池，两个 `playerContent()` 并发执行（Spider 非线程安全）。
- **JsSpider.init 非 cat 分支跨线程 parse 被空 catch 吞掉**（`JsSpider.java:132-142`）：ext 为 JSON 的源 init 静默失败，筛选配置丢失。
- **Global 的 Timer 永不 cancel + TimerTask submit 竞态**（`Global.java:34-39,301-309`）：RejectedExecutionException 未捕获可杀死 Timer 线程，该源所有 setTimeout 静默失效。
- **NativeCleaner.clean() 无人调用**（`NativeCleaner.java:47-55`）：PhantomReference 集合无界增长，setTimeout 持有的 JS 对象 native 引用永不释放。
- **ApiConfig DCL 缺 volatile**（`ApiConfig.java:67`）、**OkHttp 三字段懒初始化缺 volatile**（`OkHttp.java:35-73`）。
- **ApiConfig rules/ijk 解析缺 isJsonObject 防御**（`ApiConfig.java:601,687`）：一个畸形元素击穿整个配置加载。
- **loadJar 回调双重触发**（`ApiConfig.java:296-337`）：img 为空时用户看到两个错误对话框。
- **JarLoader 假异步**（`JarLoader.java:62-79`）：起线程后立即 `join()`，注释宣称异步实际同步阻塞调用线程 10s+。
- **Thunder 静态可变状态无同步**（`Thunder.java:30-36,138-148`）：currentTask 停错/删错任务竞态。
- **PIP 400ms postDelayed 捕获可空字段**（`PlayActivity.java:1201`、`DetailActivity.java:1164`）：销毁窗口内 NPE。
- **VodController.evaluateScript sourceBean 未判空**（`VodController.java:1660`）：WebView 回调主线程 NPE。
- **LivePlayActivity `Hashtable.contains` 误用**（`LivePlayActivity.java:884`）：查 values 恒 false；hsEpg 仍是 static Hashtable（注释称已改）。
- **History/Collect 静态 Adapter 未清理 + `HawkConfig.hotVodDelete` 静态状态跨页串扰**（`HistoryActivity.java:39` 等）。
- **BackupDialog ioExecutor 从不 shutdown**（`BackupDialog.java:45`）+ `allBackup()` 判空顺序颠倒（listFiles 可为 null）。

### 中危安全（详见安全审计报告）

- CSRF：`/action` 接受 urlencoded 表单 + 无 Origin 校验，恶意网页可静默换源（M-1）；
- 网盘凭据明文落盘 + `allowBackup="true"`（M-2，建议 EncryptedSharedPreferences）；
- WebView 4 处 `setAllowUniversalAccessFromFileURLs(true)` + MIXED_CONTENT_ALWAYS_ALLOW（M-3）；
- APK 更新无哈希/签名校验（M-4，`UpdateChecker.java:301-386`）；
- 全局明文流量放行（M-5，`network_security_config.xml:3`）；
- 三个 manifest Receiver `exported="true"` 无权限保护（S-5，改 `exported="false"` 或签名级权限）；
- CacheManager 反序列化无 filter（S-1，minSdk 27 满足 `ObjectInputFilter` 要求，或迁移 JSON 存储）；
- `/m3u8`、`/dash/` 未限环回，向局域网泄露播放内容（L-4）。

## 四、P2：结构性优化（中期重构路线图）

### 1. 消灭 PlayActivity/PlayFragment 双胞胎（第一优先级重构）

两个 2400 行类是同一个播放页的 Activity/Fragment 变体，播放编排、WebView 嗅探、JSON 解析、弹幕、字幕、m3u8 净化六件事全部内联。建议拆分：

```
com.github.tvbox.osc.play/
├── session/PlaySession.java        // 播放状态机（play/playNext/autoRetry，~300 行）
├── sniff/SniffEngine.java          // WebView/XWalk 嗅探引擎（并发容器自持，~500 行）
├── parse/JsonParseEngine.java      // doParse/parseMix + safeParseExecute（~350 行）
├── parse/M3u8Purifier.java         // m3u8 净化（去 static 状态，~120 行）
├── subtitle/TrackSelector.java     // 字幕/音轨选择（Activity/Fragment 共用，~250 行）
├── danmu/DanmuPresenter.java       // 弹幕（~150 行）
└── ui/PlayActivity|PlayFragment    // 壳：生命周期/按键（目标 <500 行）
```

LivePlayActivity（2105 行）同理拆为 LiveChannelNavigator / EpgPresenter（LRU 缓存）/ ChannelListPanel / LiveSettingPanel / LiveInfoBar。

**迁移顺序**（风险从低到高）：① 先纯拷贝同步 P0-2/3/4 三处已验证的修复 → ② 抽 TrackSelector+DanmuPresenter → ③ 抽 SniffEngine → ④ 合并 PlaySession 并处理 P0-7 注册生命周期。每步独立提交，禁止大爆炸重构。

### 2. 修复 Spider 销毁协议（native 泄漏总闸门）

建立 `SpiderContainer` 统一持有全部实例：`clear()` 时逐个走「投递到绑定线程销毁」的标准流程（P0-10 + P0-11 + Timer cancel），QuickJSContext 增加跨线程销毁的安全入口。

### 3. 拆分 ApiConfig 上帝类（964 行）

`parseJson` 单方法约 350 行、嵌套 6 层，混合六种领域解析+Hawk 持久化。按 sites/parses/lives/rules/ads/ijk 拆 6 个私有方法 + 统一 `safeAsJsonObject` 防御工具（顺带解决 rules/ijk 防御缺失）。

### 4. 统一 HTTP 栈

三套并存（catvod.net.OkHttp / OkGo / util.urlhttp），三份超时/SSL/日志配置各自为政。收敛到 `catvod.net.OkHttp`，全局超时/大小上限统一配置（顺带解决 jar 下载无大小上限、Connect buffer=1 逐字节 JNI 等问题）。

### 5. 合并跨页复制粘贴（净删 300+ 行）

- History/Collect → 泛型基类 `BaseVodListActivity<T>`；
- Search/FastSearch 的「暂停任务列表+重放+关停」→ 收敛进 SourceViewModel（`pauseAll()/resumeAll()`）；
- ModelSettingFragment 九处 SelectDialog 样板 → 抽 `showIntSelectDialog(...)` 泛型帮助方法（可砍约 400 行）；
- Thunder 的 `recursiveDelete` 与 FileUtils 重复实现 → 删除前者；
- DriveActivity 的 `sortComparator` 与 AbstractDriveViewModel 逐字符相同 → 直接用基类的。

### 6. 主线程纪律强制化

删除 `allowMainThreadQueries()`，让编译器列出全部主线程 DB 调用点，一次性完成线程迁移（UserFragment 模式已验证）。移除 `ApiConfig` useCache 路径的主线程解析、BackupDialog 构造函数 IO。

### 7. 错误可见性

全链路 `catch (Throwable) { return null/空对象 }` 遍布，故障表现为「源没数据」无线索。至少 `LOG.e(tag, e)`；关键路径（配置解析、spider init）上报结构化错误码。

## 六、值得肯定的设计

- 三通道 Loader（Jar/DexClassLoader、JS/QuickJS、Python/Chaquopy）以 `Spider` 基类为 SPI，对上层 `getCSP()` 屏蔽差异，扩展性设计合理；
- 近几轮修复引入的机制有真实工程判断：`callWithTimeout` + broken 冷却、PythonLoader 超时重建线程池、use-after-free 防护、模块编译失败降级空模块防 SIGABRT；
- 已落地的防御质量高于 TVBox 原版：路径穿越规范化、Zip Slip 防护、SSRF fail-closed 过滤、`/cache` 环回限制、XStream 白名单、**Python 侧严格证书校验**（与 Java 侧形成鲜明对比，说明团队知道正确做法）；
- Handler/EventBus/LLiveData/字幕监听器的清理在三大播放页均已验证完整。
